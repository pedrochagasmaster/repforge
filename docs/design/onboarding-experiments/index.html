Five ways to ask three questions and hand over a program

Each phone runs a working prototype of the same flow: goal, experience, schedule, a building step, then the plan as session cards. They share one answer set and one plan table, so the only thing that changes between them is structure, type and interaction. Tap inside any phone to use it, or switch every phone to the same step below.

Rules every candidate keeps

Nothing is preselected

Session length and every other answer start empty, and Continue says which answer is missing. This follows owner decisions PD-2 and PD-3 in docs/design/onboarding-g-brief.md.

The building step is honest

The compiler is synchronous, so the checklist names real compile stages using the lifter's own answers. It lasts under 3.2 seconds, a tap finishes it, and with reduced motion it completes almost at once.

No points, no streak bait

The reference shows XP on each day. Here the badges carry training facts instead: estimated minutes, exercise count, working sets and focus muscles.

Same plan everywhere

Splits, exercise counts and set totals come from one shared table, so you can compare like with like. They are illustrative and do not come from program-compiler.js.

Scope of these prototypes

Rest preference, training environment and the five-route chooser are left out to keep the comparison focused. A production slice would put them back as R4 requires.

Deep links

Each file opens on a step from its hash, for example c-plates.html#plan, and accepts a {taurifer:'goto', step} message. The gallery uses both.
