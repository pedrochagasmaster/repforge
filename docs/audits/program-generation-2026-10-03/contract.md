# Program generation audit acceptance contract

Audit source: `c1d643206d1c472b34d3f0c0e4b7cb425f571329`.
Scope: the production compiler and exercise catalogue, with the production
progression validator and authored family contract as independent consumers.
No engine behavior or activated user program will be changed.

- Deliver exactly 100 compiled representative scenarios ranked by an explicit,
  assumed joint usage prior. Retain rejected higher-ranked inputs. This is a
  conditional model, not a claim about observed users or measured likelihood.
- Deliver exactly 100 compiled stress scenarios: every one of 20 blueprints
  under five named constraint tracks using supported user choices, including
  only 30/45/60/75/90-minute budgets. Retain conflicting choice probes separately.
  Malformed-input testing is outside this audit, per the user's clarification.
- Evaluate every program across identity/structure, determinism/non-mutation,
  equipment/capabilities, slot intent, prescription bounds, progression consumer
  validity, time feasibility, preferences, exposure accounting, Foundation,
  re-entry, projection consistency, and qualitative training-quality signals.
- Evaluate each cohort and the union for coverage, output duplication,
  catalogue concentration, volume, movement/muscle exposure, conflicts,
  reductions, preferences, latency, and differential constraint response.
- Retain exact inputs, full engine outputs, individual evaluations, timings,
  source hashes, failures and replay command. Timing is descriptive on this
  machine; engine time estimates are not measured workout durations.
- Falsify the evaluator with deliberately corrupted artifacts before accepting
  the report: bad equipment, duplicated identities, excess time, invalid
  progression, false exposure, and missing protected work must be detected.
- Report observed engine defects separately from review heuristics. Coverage,
  repetition and workload heuristics are prompts for coaching review, not
  universal injury, effectiveness or clinical verdicts. No calendar/recovery
  placement, real workout outcomes, UI persistence or physical equipment
  availability is proved by this pure compiler audit.

Independent meanings come from `docs/program-family-design.md`,
`docs/plan-047-owner-approved-design.md`,
`plans/047-owner-approved-amendment.md`,
`test/fixtures/program-family-contract-v1.json`, and `progression-engine.js`.
Executable blueprint/class data is also used to identify exact affected slots;
shared-source checks are explicitly weaker than independent consumer checks.
