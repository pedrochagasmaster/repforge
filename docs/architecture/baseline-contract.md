## Data-interface hazards to retain in review

1. Unknown-field preservation and strict import validation are different responsibilities. Do not apply an input validator as a destructive stored snapshot normalizer: malformed/unknown profile remains user data even when the visible form cannot render it.
2. State commits, draft publication and irreversible transfer commit have distinct settlement rules. A generic `save()` interface would erase checkpoint/lock/outcome distinctions; commands need explicit observable outcomes and recovery retention.
3. Source catalogue UUID, program slot ID, set ID, generated program identity and workout session ID are not interchangeable. The frozen row keeps separate source/performed UUID and slot identity intentionally.
4. A frozen pure command result cannot attest IndexedDB/localStorage convergence. Existing browser crash/race proofs remain required when changing the storage owner, including previous-release writer fixtures with their matching shell.
5. History's repeated metric representations and loading context must remain coherent. Preserve full rows through import/export and aggregation; do not derive loading truth from a current catalogue that may have changed since the workout.
6. Pending worker generations need cancellation/epoch ownership at the page client. Thread extraction cannot move page state into shared domain globals or change synchronous setup-link regeneration into a write before confirmation.
