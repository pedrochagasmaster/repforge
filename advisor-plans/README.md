# Advisor implementation plans

Generated by the `improve` skill on 2026-09-22/23: a deep audit (plans
001–022, written against `ff9991cf`) and a direction pass (plans 023–027,
written against `76a31602`). Each plan is self-contained and written for an
executor with no prior context.

**Which code these plans describe:** both planning SHAs are on the Plan 057
branch (`origin/ui-overhaul/057-management-surfaces`, draft PR #248), **not yet
on `main`**. Excerpts therefore describe post-057 code. Run each plan's drift
check against the branch you execute on. If PR #248 has not merged, execute on
top of it, or expect STOP conditions to trigger.

**Why this directory and not `plans/`:** `plans/` is the project's own governed
plan series (Plans 001–061, owner gates, the UI-overhaul DAG). These advisor
plans are *proposals*. Per `CLAUDE.md` and `docs/backlog.md`, the backlog is the
only work queue ("If work isn't here, it isn't scheduled"), so the owner must
accept a plan into `docs/backlog.md`, or approve it directly, before an executor
runs it. Plan numbers here are independent of `plans/NNN`.

**Before executing any plan:** run `git status` first, and never mix another
person's uncommitted changes into an advisor-plan commit. Every plan that edits
a precached file includes the cache-revision ritual (`sw.js` `CACHE` + every
`?v=NN` in `sw.js` and `index.html` + `expectedRevision` in
`test/exercise-library.mjs`). Because every such plan bumps the same number,
**run them one at a time**, never in parallel branches.

## Findings considered and rejected

- **Make the Motion/@dnd-kit precache best-effort** (audit PERF-03): rejected. The atomic precache is deliberate, and `test/vendor-runtimes.mjs:76` asserts "the runtime and layer are atomically precached" for identical offline behavior.
- **"`app.js` keeps growing / `durable-state.js` is a host-adapter shell"** (ARCH-01): rejected as a standalone plan. It is already governed by `docs/taurifer-architecture-refactoring-plan.md` (candidates A–H) and its owner-ratified disposition into the bridge and Plans 055–059. The host adapter *is* the ratified facade (R5), with delegate removal assigned to 058 and verification to 059. Only the concrete hidden-global leak became plan 016.
- **Debounce the picker input** (PERF-02 sub-item): rejected. It adds latency and breaks tests that read the list right after `fill`; caching removes the cost.
- **Security category**: no HIGH/MED findings. Install-transfer crypto (AES-256-GCM/HKDF), replay protection, constant-time comparisons, prototype-pollution guards, universal `esc()` before `innerHTML`, enum-only telemetry, and cookie attributes all match or exceed ADRs 0007/0013. `npm audit` is clean for `test/` and `services/install-transfer/`.
- **Test deps (playwright/fast-check) minor lag**: normal lag, no advisory; not worth a plan.
- **Other empty `catch{}` blocks in `durable-state.js`** (best-effort key enumeration): consistent with the file's failure posture; not findings.
- **Direction: general friction/lifecycle observability beyond the allowlist**: not proposed. The existing registry already covers skips, overrides, and abandonment; 023 wires what is approved.
